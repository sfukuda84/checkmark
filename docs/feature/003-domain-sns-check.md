# ドメイン・SNS の空き確認

**状態**: 未着手 | **区分**: MVP | **想定順序**: 3 | **依存**: 001-trademark-batch-check

## 概要

一括チェックの各候補について、利用者が選んだ TLD のドメインが取得できるかと、X・Instagram・YouTube・TikTok で同じアカウント名が使われているかを確かめる。結果は `001-trademark-batch-check` の比較表に列として加わり、名前を決めた後に必要になるドメインと SNS アカウントの確保の見通しまで 1 画面で分かる。

## 位置づけ

中核価値（premises P1）のうち、商標と Web 検索に加えて「その名前を実際に使えるか」を確かめる部分を担う。競合では NAZUKE だけが持つ機能である（competitor.md §1.2）。チェックの実行と比較表は `001-trademark-batch-check` に依存する。

## 主な要求

- **ドメインの空き確認**:
  - 一括チェックの実行時に、確かめる TLD を利用者が選べる
  - 候補ごと・TLD ごとに、取得できるか（空き／取得済み）を示す
- **SNS アカウント名の空き確認**:
  - 候補ごとに、X・Instagram・YouTube・TikTok で同じアカウント名が使われているかを示す
  - 使われている場合は、そのアカウントを開ける
  - 候補名がそのままアカウント名に使えない文字を含む場合は、確かめたアカウント名が分かるように示す
- **一括チェックへの組み込み**:
  - 比較表にドメインと SNS の列が加わる
  - 確かめられなかったもの（相手側の制限など）は「不明」として示し、やり直せる

主なエンティティ: ドメイン確認結果（候補 × TLD）、SNS 確認結果（候補 × SNS）

## 前提・設計原則との関係

- **共通標準**: チェック・候補・比較表は `001-trademark-batch-check` のものを使う。ドメインと SNS の確認手段は `docs/architecture.md` で決める
- **固有の制約**: 各 SNS の利用規約に反する方法（禁止されている自動取得など）で確かめてはならない。確かめられない場合は「不明」として示す。外部への送信は確認に必要な範囲に限る（Q11）

## スコープ外

- ドメインの取得代行や、SNS アカウントの作成
- 4 つ以外の SNS
- 選べる TLD の一覧、アカウント名に変換する規則は `/speckit-clarify` と `/speckit-plan` で決める
