# 運用基盤

**状態**: 未着手 | **区分**: MVP | **想定順序**: 999 | **依存**: 000-app-basic, 005-operator-console

## 概要

本番公開の前に、運営者が兼任でサービスを運用できる仕組みをそろえる。対象は、`main` へのマージによる本番への自動デプロイと切り戻し、停止とエラーとリソースの監視、日次バックアップとリストアの確認、ログのローテーション、依存ライブラリの脆弱性スキャン、費用の上限に応じた有料 API の自動停止、運用手順書である。

## 位置づけ

`docs/nfr.md` の横断要件のうち、1 回作れば全体に効く仕組みを実装する機能である。MVP の最後に着手し、これがそろったら本番に公開する。品質ゲート（CI）は `000-app-basic` で先に入れる。費用の集計は `005-operator-console` のものを使う。

## 主な要求

- **デプロイ**:
  - `main` へのマージで、本番へ自動でデプロイされる。デプロイの成否が運営者に分かる
  - 直前の版へ手動で切り戻せる
  - データベースのマイグレーションは、デプロイの一部として適用される
- **監視とアラート**:
  - 外部から 5 分間隔で稼働を確かめ、停止したら運営者にメールで知らせる
  - アプリのエラーの急増を運営者に知らせる。通知に候補名を含めない
  - ディスクとメモリの使用率が 80% を超えたら知らせる
- **バックアップとリストア**:
  - アプリのデータを毎日バックアップし、14 世代を国外に置いてよい保存先に保持する
  - バックアップの失敗を運営者に知らせる
  - バックアップから別の環境へ復元する手順があり、月 1 回の確認を記録できる
- **ログ**:
  - アプリのログを 30 日でローテーションする。ログにパスワード、トークン、候補名を残さない
- **脆弱性と依存ライブラリ**:
  - 依存ライブラリの既知の脆弱性を自動で検出し、運営者に知らせる
- **費用の上限**:
  - 月の費用の見込みが上限の 80% に達したら運営者に知らせる。100% に達したら、有料の外部 API（Google 検索）の呼び出しを自動で止める。止めている間は、その項目を「不明」と示す。月が変わるか運営者が解除したら再開する
- **サーバーの基本設定**:
  - VPS の初期設定（SSH の公開鍵認証、root ログインの禁止、公開ポートの制限、OS のセキュリティ更新の自動適用）を、手順として再現できる
- **運用手順書**:
  - 障害からの復旧、リストア、商標マスタの取り込み、デプロイの切り戻しの手順を文書に残す

主なエンティティ: デプロイの記録、バックアップの記録、リストア確認の記録、費用の上限による停止の状態

## 前提・設計原則との関係

- **共通標準**: デプロイは GitHub Actions、GHCR、SSH で行う。バックアップは `pg_dump` と Cloudflare R2、エラー通知は Sentry、外形監視は UptimeRobot を使う（docs/architecture.md §3）。対応する横断要件は、NFR-AV-003、NFR-DA-001〜005、NFR-SE-003、NFR-SE-004、NFR-SE-008、NFR-OP-001〜004、NFR-OP-006、NFR-CT-002
- **固有の制約**: 監視、通知、ログに候補名を含めない（憲章 II）。UptimeRobot Free を商用で使ってよいかは確認が要る（docs/architecture.md §9 R6）

## スコープ外

- リンター、型検査、テストの自動実行（CI）（`000-app-basic` で入れる。NFR-OP-005）
- 運営者による費用の集計画面（`005-operator-console` が扱う）
- 冗長化や自動のフェイルオーバー（NFR-AV-001 で目標を設けない）
- 監視の閾値の細部、デプロイの方式の細部は `/speckit-clarify` と `/speckit-plan` で決める

## 根拠

- docs/nfr.md: NFR-AV-003、NFR-DA-001〜005、NFR-SE-003・004・008、NFR-OP-001〜004・006、NFR-CT-002
- premises.md Q24〜Q31: 非機能要件のヒアリング（可用性の目標なし、RPO 24 時間・保持 14 日、性能、互換性、監視、ログ、費用の上限、CI の位置）
- docs/architecture.md §3、§5: 運用の方式と月額の予算
- 区分の判断根拠: 本番公開の前に必要なため、MVP の最後に置く
