# Google 検索の使用状況チェック

**状態**: 未着手 | **区分**: MVP | **想定順序**: 2 | **依存**: 000-app-basic, 001-trademark-batch-check

## 概要

一括チェックの各候補について、Google 検索での上位の結果を示し、候補名がそのまま使われているかで「該当あり／なし」の目安を自動で付ける。結果は `001-trademark-batch-check` の比較表に列として加わり、商標と Web 上の使用状況を 1 画面で見比べられる。

## 位置づけ

コンセプトの「商標登録と Google 検索結果の該当ありなしを同時に」の後半を担う、このサービスの差別化の中心である（competitor.md §1.3: 調べた商標検索サービスは Web 検索の結果を示していない）。チェックの実行と比較表は `001-trademark-batch-check` に依存する。

## 主な要求

- **Google 検索の結果の表示**:
  - 候補ごとに、Google 検索の上位の結果（タイトル、URL、抜粋）を一覧で示す
  - 結果のリンクから、元のページを開ける
- **該当の目安**:
  - 候補名が結果のタイトルなどにそのまま含まれるかで、「該当あり／なし」の目安を自動で付ける
  - 目安の根拠になった結果が分かるように示す
  - 目安は機械的な判定であり、同業種での使用かどうかは利用者が確かめる必要があることを明示する
- **一括チェックへの組み込み**:
  - 一括チェックを実行すると、商標の照合とあわせて Google 検索のチェックも行われる
  - 比較表に Google 検索の列が加わり、候補ごとの目安が並ぶ
  - 検索に失敗した候補は、失敗したことと、やり直せることを示す

主なエンティティ: Web 検索結果（候補ごとの上位結果の一覧と、該当の目安）

## 前提・設計原則との関係

- **共通標準**: チェック・候補・比較表・利用回数の上限は `001-trademark-batch-check` のものを使う。検索結果の取得手段は `docs/architecture.md` で決める
- **固有の制約**: Google の公式検索 API（Custom Search JSON API）は新規受付を止めており、2027-01-01 に終了する（competitor.md §1.4）。取得手段はこれを前提に選ぶ。検索サービスへ送るのは候補名など検索に必要な情報だけにする（Q11）。外部 API の費用が件数に比例するため、利用回数の上限の対象にする（Q16）

## スコープ外

- AI による同業種での使用の判定（backlog BL-005）
- Google 以外の検索エンジンの結果（Q5 で Google の結果が必要と決めた）
- 取得する上位の件数、一致の判定規則の細部は `/speckit-clarify` と `/speckit-plan` で決める

## 根拠
