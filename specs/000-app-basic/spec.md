# Feature Specification: アプリ基盤

**Feature Branch**: `feature/000-app-basic`

**Created**: 2026-09-23

**Status**: Draft

**Input**: User description: "アプリ基盤。利用者は、メールアドレスとパスワード（メールアドレスの確認つき）または Google アカウントでサインアップ・ログインでき、ログアウトと、メールによるパスワードの再設定ができる。ログインしたままメールアドレスを変更でき、新しいアドレスの確認を終えてから反映される。退会すると、本人のアカウント情報、チェック、候補名、結果がすべて削除される。サインアップの時に利用規約（結果は簡易チェックであり法的判断ではないという免責を含む）とプライバシーポリシーへ同意し、改定時には再同意を求め、同意の履歴を残す。初回訪問時に Cookie の同意を求める。確認や再設定のメールを送る。アカウントには利用者か運営者のロールと、有効か停止の状態があり、停止されたアカウントはログインできない。メンテナンス中はその旨を示す。すべての PR でリンター、型検査、単体テスト、E2E テストを自動で実行し、通らない変更はマージできないようにする。運営者向け画面の中身、お問い合わせ、多要素認証、パスキー、組織と招待、決済は含まない。"

## Clarifications

### Session 2026-09-23 (Round 1)

- Q: メールアドレスとパスワードで登録済みの人が、同じアドレスの Google アカウントでログインしたとき、どう扱うか？ → A: Google 側で確認済みのアドレスに限り、既存のアカウントに Google のログイン手段を自動で結びつける
- Q: Google アカウントだけで登録した人は、メールアドレスを変えたりパスワードを設定したりできるか？ → A: どちらもできない。メールアドレスは Google アカウントのものを使う
- Q: 退会するときに、本人確認をどこまで求めるか？ → A: 再認証（パスワードの再入力、または Google でのログインし直し）を求める。メールアドレスの変更も同じにする
- Q: 確認リンクの有効期限と未確認アカウントの保持期間はいくつにするか？ → A: メールアドレスの確認と変更は 24 時間、パスワードの再設定は 1 時間、未確認のアカウントは 7 日で削除する

## User Scenarios & Testing *(mandatory)*

### User Story 1 - メールアドレスとパスワードで登録してログインする (Priority: P1)

名付け担当者が、メールアドレスとパスワードでアカウントを作る。利用規約とプライバシーポリシーに同意し、届いた確認メールでメールアドレスを確かめると、ログインしてサービスを使い始められる。使い終わったらログアウトし、次回は同じメールアドレスとパスワードでログインする。

**Why this priority**: 以降のすべての機能（一括チェック、履歴など）は、ログインした個人アカウントを前提にする。これがなければ、ほかの機能を提供できない。

**Independent Test**: 新しいメールアドレスでサインアップし、確認メールのリンクを開き、ログイン、ログアウト、再ログインまでを行って確かめられる。ログインした人だけが入れるページに入れることで、価値を確かめられる。

**Acceptance Scenarios**:

1. **Given** 未登録のメールアドレスを持つ訪問者, **When** メールアドレスとパスワードを入力し、利用規約とプライバシーポリシーに同意してサインアップする, **Then** アカウントが作られ、そのアドレスに確認メールが届き、確認が済むまで使えないことが示される
2. **Given** 確認メールを受け取った利用者, **When** メールのリンクを開く, **Then** メールアドレスが確認済みになり、ログインした状態になる
3. **Given** 利用規約とプライバシーポリシーに同意していない訪問者, **When** サインアップしようとする, **Then** サインアップできず、同意が必要であることが示される
4. **Given** 確認済みの利用者, **When** 正しいメールアドレスとパスワードでログインする, **Then** ログインした状態になる
5. **Given** ログインしている利用者, **When** ログアウトする, **Then** ログインが必要なページに入れなくなる
6. **Given** 利用者, **When** 誤ったパスワードでログインしようとする, **Then** ログインできず、メールアドレスとパスワードのどちらが誤っているかは示されない

---

### User Story 2 - Google アカウントで登録・ログインする (Priority: P1)

パスワードを増やしたくない利用者が、Google アカウントで登録してログインする。初回だけ利用規約とプライバシーポリシーに同意する。

**Why this priority**: 個人・中小企業の利用者にとって、登録の手間が少ないことは利用開始の障壁を下げる（premises Q19 で MVP に含めると決めた）。

**Independent Test**: Google アカウントでの初回登録（同意を含む）、ログアウト、再ログインを行って確かめられる。

**Acceptance Scenarios**:

1. **Given** 未登録の訪問者, **When** Google アカウントで登録を選び、Google 側で許可し、利用規約とプライバシーポリシーに同意する, **Then** アカウントが作られ、ログインした状態になる
2. **Given** Google アカウントで登録済みの利用者, **When** Google アカウントでログインする, **Then** 同意を求められずにログインした状態になる
3. **Given** メールアドレスとパスワードで登録済みの利用者, **When** 同じアドレスの Google アカウント（Google 側で確認済み）でログインする, **Then** 既存のアカウントに Google のログイン手段が結びつき、同じ履歴のままログインした状態になる
4. **Given** 訪問者, **When** Google 側で許可を取り消した（キャンセルした）, **Then** アカウントは作られず、登録画面に戻る

---

### User Story 3 - パスワードを忘れたときに再設定する (Priority: P2)

パスワードを忘れた利用者が、メールアドレスを入力して届いたメールのリンクから新しいパスワードを設定し、再びログインできるようにする。

**Why this priority**: パスワードでログインする利用者が自力で復帰できないと、アカウントを失う。ただし、ログインそのもの（US1）がなければ意味がないため P2 とする。

**Independent Test**: 再設定を依頼し、メールのリンクから新しいパスワードを設定し、そのパスワードでログインできること、古いパスワードではログインできないことを確かめる。

**Acceptance Scenarios**:

1. **Given** 登録済みの利用者, **When** メールアドレスを入力して再設定を依頼する, **Then** 再設定用のメールが届く
2. **Given** 未登録のメールアドレス, **When** 再設定を依頼する, **Then** 登録済みのときと同じ案内が表示され、登録の有無は分からない
3. **Given** 再設定用のメールを受け取った利用者, **When** リンクを開いて新しいパスワードを設定する, **Then** 新しいパスワードでログインでき、ほかの端末のログイン状態は解除される
4. **Given** 有効期限が切れた、または一度使った再設定リンク, **When** 開く, **Then** 使えないことが示され、再設定をもう一度依頼できる

---

### User Story 4 - メールアドレスを変更する・退会する (Priority: P2)

利用者が、ログインしたままメールアドレスを新しいものに変える。サービスをやめるときは退会し、自分のデータがすべて消えることを確かめる。

**Why this priority**: 候補名は機密情報になりうるため、本人が自分のデータを確実に消せることは憲章 II の要件である。ただし、ログイン（US1、US2）が前提になるため P2 とする。

**Independent Test**: メールアドレスを変更し、新しいアドレスの確認後に新しいアドレスでログインできることを確かめる。退会し、同じ手段でログインできないこと、本人のデータが残っていないことを確かめる。

**Acceptance Scenarios**:

1. **Given** パスワードでログインできる利用者, **When** 再認証を済ませ、新しいメールアドレスを入力して変更を依頼する, **Then** 新しいアドレスに確認メールが届き、確認が済むまでは古いアドレスのまま使える
2. **Given** 変更の確認メールを受け取った利用者, **When** リンクを開く, **Then** メールアドレスが新しいものに変わり、古いアドレスに変更があったことが知らされる
3. **Given** ログインしている利用者, **When** ほかのアカウントが使っているメールアドレスへの変更を依頼する, **Then** 変更はできず、ほかのアカウントの存在は分からない
4. **Given** ログインしている利用者, **When** 退会を選び、再認証を済ませて確認に同意する, **Then** アカウント情報と、本人のチェック、候補名、結果がすべて削除され、ログアウトした状態になる
5. **Given** 退会した利用者, **When** 同じメールアドレスでログインしようとする, **Then** ログインできない（同じアドレスで新しく登録し直すことはできる）
6. **Given** Google アカウントだけで登録した利用者, **When** アカウント設定を開く, **Then** メールアドレスの変更とパスワードの設定はできず、メールアドレスは Google アカウントのものを使うことが示される
7. **Given** ログインしている利用者, **When** 再認証に失敗する, **Then** 退会もメールアドレスの変更も行われない

---

### User Story 5 - 規約の改定と Cookie に同意する (Priority: P3)

利用規約やプライバシーポリシーが改定されたら、利用者は次にログインしたときに新しい版に同意してから使い続ける。初めて訪れた人には Cookie の利用について同意を求め、必須でない Cookie は同意するまで使わない。

**Why this priority**: 法令と信頼の面で必要だが、初回の同意（US1、US2）で最低限は満たせるため P3 とする。

**Independent Test**: 規約の版を上げてからログインし、再同意の画面が出ること、同意の履歴に新しい版が残ることを確かめる。初回訪問で Cookie の同意が求められ、拒否した場合に必須でない Cookie が使われないことを確かめる。

**Acceptance Scenarios**:

1. **Given** 旧版の規約に同意済みの利用者, **When** 規約が改定された後にログインする, **Then** 新しい版への同意を求められ、同意するまでサービスを使えない
2. **Given** 利用者, **When** 規約に同意する, **Then** どの版にいつ同意したかが記録される
3. **Given** 初めて訪れた人, **When** ページを開く, **Then** Cookie の利用について同意を求められる
4. **Given** 必須でない Cookie を拒否した人, **When** サービスを使う, **Then** 必須でない Cookie は使われず、サービスの主な機能はそのまま使える

---

### User Story 6 - 運営者と利用者を区別し、停止とメンテナンスを反映する (Priority: P3)

アカウントには「利用者」か「運営者」のロールと、「有効」か「停止」の状態がある。運営者だけが運営者向けの画面に入れる。停止されたアカウントはログインできない。更新作業の間は、訪れた人にメンテナンス中であることを示す。

**Why this priority**: 運営者向けの画面の中身（`005-operator-console`）の前提になるが、利用者の最初の価値には直接効かないため P3 とする。

**Independent Test**: 利用者のアカウントで運営者向けの画面に入れないこと、停止にしたアカウントでログインできないこと、メンテナンス中にしたらその表示が出ることを確かめる。

**Acceptance Scenarios**:

1. **Given** ロールが「利用者」のアカウント, **When** 運営者向けの画面を開く, **Then** 入れない
2. **Given** ロールが「運営者」のアカウント, **When** 運営者向けの画面を開く, **Then** 入れる
3. **Given** 状態が「停止」のアカウント, **When** ログインしようとする, **Then** ログインできず、利用が停止されていることと問い合わせ先が示される
4. **Given** ログイン中のアカウントが停止された, **When** 次に操作する, **Then** ログアウトした状態になり、停止されていることが示される
5. **Given** サービスがメンテナンス中, **When** 利用者がページを開く, **Then** メンテナンス中であることが示される

---

### Edge Cases

- 確認メールが届かない場合: 確認メールを送り直せる。送り直しの回数には上限がある
- 確認が済まないまま放置されたアカウント: 一定期間を過ぎたら削除し、同じアドレスで登録し直せる
- 既にメールアドレスとパスワードで登録済みのアドレスと同じ Google アカウントでログインした場合: Google 側で確認済みのアドレスなら、既存のアカウントに結びつける。確認されていなければ結びつけず、既存の手段でのログインを案内する
- Google アカウントだけで登録した人がパスワードの再設定を依頼した場合: 登録済みのときと同じ案内を表示する。メールでは、Google でログインするよう案内する
- 同じメールアドレスで二重にサインアップしようとした場合: 新しいアカウントは作られず、登録の有無が分からない案内を出す
- ログインや再設定を短時間に繰り返した場合: 試行回数の制限に達したら、しばらく受け付けない（NFR-SE-006）
- 退会の途中で処理が失敗した場合: 一部のデータだけが残る状態にしない。失敗したら退会は完了しない
- 運営者のロールを持つアカウントが退会する場合: 退会できる（ただし運営者が 0 人になる場合は、運営者の追加方法を運用手順で定める）
- 規約の同意画面で同意しなかった場合: ログアウトはできるが、サービスは使えない
- 確認・再設定・変更のメールが送れなかった場合: 利用者に送れなかったことを示し、あとで送り直せる

## Requirements *(mandatory)*

### Functional Requirements

**サインアップとログイン**

- **FR-001**: System MUST 訪問者がメールアドレスとパスワードでサインアップできるようにする
- **FR-002**: System MUST パスワードに、8 文字以上であることと、既知の漏えいパスワードでないことを求める（NFR-SE-005）
- **FR-003**: System MUST サインアップしたメールアドレスに確認メール（リンクの有効期限は 24 時間）を送り、確認が済むまでサービスの機能を使わせない
- **FR-003a**: System MUST 登録から 7 日を過ぎても確認が済まないアカウントを削除する
- **FR-004**: Users MUST be able to 確認メールを送り直せる
- **FR-005**: System MUST 訪問者が Google アカウントでサインアップ・ログインできるようにする
- **FR-005a**: System MUST Google 側で確認済みのメールアドレスが既存のアカウントと一致する場合、そのアカウントに Google のログイン手段を自動で結びつける。確認されていない場合は結びつけない
- **FR-006**: Users MUST be able to 確認済みのメールアドレスとパスワード、または Google アカウントでログインし、ログアウトできる
- **FR-007**: System MUST ログインの失敗時に、メールアドレスとパスワードのどちらが誤っているか、アカウントが存在するかを示さない
- **FR-008**: System MUST ログインとパスワード再設定の試行回数を、アカウントと接続元ごとに制限する（NFR-SE-006）

**パスワードの再設定**

- **FR-009**: Users MUST be able to メールアドレスを入力して、パスワード再設定用のメールを受け取れる。未登録のアドレスでも同じ案内を表示する
- **FR-010**: System MUST 再設定用のリンクを、有効期限 1 時間かつ 1 回限りのものにする
- **FR-011**: System MUST パスワードを再設定したら、その利用者のほかのログイン状態をすべて解除する

**アカウント**

- **FR-012**: Users MUST be able to パスワードでログインできるアカウントなら、再認証を済ませたうえで、メールアドレスの変更を依頼できる。新しいアドレスの確認（リンクの有効期限は 24 時間）が済むまで変更を反映しない
- **FR-012a**: System MUST Google アカウントだけのアカウントでは、メールアドレスの変更とパスワードの設定を受け付けない
- **FR-013**: System MUST メールアドレスを変更したら、古いアドレスに変更があったことを知らせる
- **FR-014**: System MUST ほかのアカウントが使っているメールアドレスへの変更を受け付けず、その理由からほかのアカウントの存在が分からないようにする
- **FR-015**: Users MUST be able to 再認証（パスワードの再入力、または Google でのログインし直し）と確認を経て退会できる
- **FR-016**: System MUST 退会したら、本人のアカウント情報、ログイン手段、同意の履歴、チェック、候補名、結果を、アプリのデータから復元できない形ですべて削除する。削除は全部か無しかで行う（憲章 II、NFR-DA-004）

**同意**

- **FR-017**: System MUST サインアップの時に、利用規約とプライバシーポリシーへの同意を求める。同意しない限りアカウントを作らない
- **FR-018**: System MUST 利用規約に、チェックの結果が簡易チェックであって、商標登録の可否などの法的判断ではないことを含める（憲章 IV）
- **FR-019**: System MUST 利用規約とプライバシーポリシーを版で管理し、改定された版に未同意の利用者には、次の利用時に同意を求め、同意するまで機能を使わせない
- **FR-020**: System MUST 利用者がどの文書のどの版にいつ同意したかを記録する
- **FR-021**: System MUST 初回の訪問時に Cookie の利用について同意を求め、必須でない Cookie は同意があるまで使わない。同意の選択はあとから変えられる

**トランザクションメール**

- **FR-022**: System MUST メールアドレスの確認、パスワードの再設定、メールアドレスの変更の確認と通知を、利用者にメールで送る
- **FR-023**: System MUST メールを送れなかった場合に、利用者にそれを示し、送り直せるようにする

**ロール、状態、メンテナンス**

- **FR-024**: System MUST すべてのアカウントに、「利用者」か「運営者」のロールと、「有効」か「停止」の状態を持たせる。サインアップで作ったアカウントは「利用者」かつ「有効」とする
- **FR-025**: System MUST 運営者向けの画面には、ロールが「運営者」のアカウントだけを入れる
- **FR-026**: System MUST 状態が「停止」のアカウントのログインを拒み、ログイン中であれば次の操作でログアウトさせ、停止されていることを示す
- **FR-027**: System MUST 運営者のロールの付与は、運用手順（画面ではない方法）でのみ行えるようにする
- **FR-028**: System MUST メンテナンス中は、利用者が開いたページでメンテナンス中であることを示す（NFR-AV-003）

**品質ゲート**

- **FR-029**: System MUST すべての変更の提案（プルリクエスト）で、静的検査、型検査、単体テスト、E2E テストを自動で実行し、どれかが通らない変更は取り込めないようにする（NFR-OP-005、憲章 V）

**秘密情報と記録**

- **FR-030**: System MUST ログにパスワード、トークン、セッションの識別子を残さない（NFR-SE-004）

### Key Entities

- **アカウント**: サービスを使う個人。メールアドレス（一意）、メールアドレスの確認状態、ロール（利用者／運営者）、状態（有効／停止）、登録日時を持つ
- **ログイン手段**: アカウントに結びつくログインの方法。メールアドレスとパスワード、または Google アカウント。1 つのアカウントに両方を結びつけられる（FR-005a）
- **ログイン状態（セッション）**: アカウントがログインしている端末ごとの状態。ログアウト、パスワードの再設定、停止で解除される
- **確認用のリンク**: メールアドレスの確認、パスワードの再設定、メールアドレスの変更に使う、有効期限付き・1 回限りのもの
- **規約の版**: 利用規約とプライバシーポリシーの版と、その施行日
- **同意の履歴**: どのアカウントが、どの文書のどの版に、いつ同意したか
- **Cookie の同意**: 訪問者の端末ごとの、必須でない Cookie の利用への同意の選択

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 初めての利用者が、メールアドレスとパスワードでのサインアップから確認を経てログインするまでを、3 分以内に終えられる（確認メールの到着待ちを除く）
- **SC-002**: Google アカウントでの初回登録を、1 分以内に終えられる
- **SC-003**: 確認・再設定のメールの 95% が、依頼から 1 分以内に届く
- **SC-004**: 退会した利用者のアカウント情報、チェック、候補名、結果が、退会の直後にアプリのデータに 1 件も残っていない
