# Research: 候補名の一括チェックと商標照合

**Feature**: `001-trademark-batch-check` | **Date**: 2026-09-23

## R1. 商標データの取得と取り込み

- **Decision**:
  - 照合の対象は、自前の PostgreSQL に取り込んだ商標データ（`trademark_marks`、`trademark_readings`）とする（`docs/architecture.md` §2.1）。
  - 取り込みは新しい実行単位 `apps/importer`（CLI、手動起動）で行う。入力は「取り込み用 TSV」（列は contracts/jobs-and-cli.md §3）とし、特許庁の一括ダウンロードの TSV から取り込み用 TSV への変換は、`packages/trademark` の `JpoBulkMapping` の 1 か所に閉じ込める。
  - 取り込みの単位を「データセット」とし、基準日（どの時点までの出願・登録を含むか）と取り込み日時を持たせる。全件の取り込みが終わるまで、前のデータセットを照合に使う（途中の状態を見せない）。
  - 権利が消滅した商標（FR-010a）は取り込まない。差分の取り込みで消滅になった商標は削除する。
- **Rationale**:
  - 特許庁の一括ダウンロードの項目定義書は、利用申込（`docs/architecture.md` §9 R1）の後でなければ確かめられない（2026-09-23 の時点で、公開の資料 https://www.jpo.go.jp/system/laws/sesaku/data/download.html と提供データ一覧 https://www.jpo.go.jp/system/laws/sesaku/data/document/download/01.pdf は、自動の取得を拒まれて本文を確認できなかった）。変換を 1 か所に閉じ込めれば、項目定義書が手に入ったときの変更がそこだけで済む（憲章 III）。
  - clarify 1 回目の決定（検証用データで先に作る）に沿う。開発と検証は、取り込み用 TSV の形式の検証用データ（`apps/importer/fixtures/`）で行う。
- **Alternatives considered**:
  - 特許情報取得 API で都度照会する: 1 日 400〜800 件の上限があり、称呼の類似検索の API もないため却下。
  - J-PlatPat の画面の自動取得: 規約で禁止されている（憲章 III）。

## R2. 候補の正規化と入力の検証

- **Decision**:
  - 正規化は、Unicode NFKC → ひらがなをカタカナに → 英字を小文字に → 連続する空白を 1 つにして前後を除く、の順で行う。同一の判定（FR-003、FR-008）は、この正規化後の文字の一致で行う。
  - 使える文字（FR-004）は、NFKC の後でひらがな、カタカナ、漢字（CJK 統合漢字と拡張 A）、英数字、空白、`ー`、記号 `- ・ & . ' ! ? + ,` とする。絵文字と制御文字を含む候補は拒む。長さは NFKC の後の文字数（書記素ではなくコードポイント）で 50 以内とする。
  - 読みの入力は `候補名 / ヨミ` の形（区切りは `/`。全角の `／` も NFKC で `/` になる）で、1 行に書く。読みは NFKC の後にひらがなをカタカナにし、カタカナと `ー` だけを受け付ける。
- **Rationale**: `/` は使える文字に含めないので、区切りとして曖昧にならない。1 つの入力欄に貼り付けられるので、FR-001 の「1 行に 1 件」を保てる。
- **Alternatives considered**: 候補ごとに読みの入力欄を並べる形は、貼り付けの手間が増えるため採らなかった。

## R3. 読みの推定（FR-014）

- **Decision**: 次の順で、最初に得られた読みを使う。推定したかどうかを候補に記録する。
  1. 利用者が添えた読み（推定ではない）
  2. 候補がカタカナ・ひらがなと `ー` だけなら、その文字自体（推定ではない）
  3. 正規化後の文字が同じ既存の商標があれば、その称呼のうち最も多く使われているもの
  4. 漢字を含むなら、kuromoji（IPADIC の辞書）の形態素解析の読みをつなげたもの
  5. 英字は、wanakana でローマ字として読めればそのカナ。読めなければ、アルファベットの読み（エー、ビー、シー…）をつなげたもの（正規化で小文字になるため、大文字の略語かどうかは区別しない。英単語は 3 の既存商標の称呼で拾う）
  6. 数字は、1 桁ずつの読み（イチ、ニ…）にする
  - 推定できない文字（記号など）は読みから除く。読みが空になった候補は「不明」ではなく、同一の判定だけを行い、類似は「読みを添えてください」と示す。
- **Rationale**: ユーザーが S5 で「形態素解析辞書＋商標データ」を選んだ。3 で既存商標の称呼を流用すると、英語の商標（APPLE → アップル）でも実データに沿う読みになる。
- **費用と資源（憲章 VI）**: kuromoji 0.1.2（Apache-2.0、辞書を含めて約 41MB）と wanakana 5.3.1（MIT）を `packages/trademark` の依存に足す。月額への影響はない。kuromoji の辞書は、漢字を含む候補の推定が要るときだけ worker で読み込み、10 分使わなければ手放す（常駐させない）。読み込むとメモリを約 390MB 使う（2026-09-23 の実測: RSS 45MB → 434MB、読み込みは約 0.2 秒）。使う間だけ worker が約 450MB になるが、VPS 2GB の中で web と PostgreSQL の分を差し引いても収まる。メモリの使用率は運用基盤の監視（NFR-OP-001、80% 超で通知）で見張る。web では読み込まない。
- **Alternatives considered**: 商標データとローマ字の変換だけにする案（辞書なし）は、漢字の候補の推定ができないため採らなかった。外部の読み仮名 API は、候補名を外部に送る範囲が広がる（憲章 II）ため採らなかった。

## R4. 称呼の類似の検索と順位づけ（FR-009、SC-004）

- **Decision**:
  - 読み（カタカナ）を「称呼キー」に変換して持つ。称呼キーは、読みをモーラに分けてから wanakana でローマ字（ASCII の小文字）にしたものとする。長音 `ー` は直前の母音になり（ラーメン → raamen）、拗音は 1 音として扱う（キャ → kya）。
  - 候補の抽出（DB）: `pg_trgm` の GIN 索引で `similarity(reading_key, $key) >= 0.3` のものを最大 300 件取り出す。称呼キーが 4 文字未満の場合は trigram が効きにくいため、先頭 1 文字が同じで長さの差が 2 以内のものも、btree 索引で最大 300 件取り出す。
  - 順位づけ（アプリ）: モーラ（仮名 1 拍）の列の重み付き編集距離で似ている度合い（0〜1）を計算する。置換の重みは、清音と濁音・半濁音の違い（カ↔ガ、ハ↔バ↔パ）、同じ行の母音違いを 0.5、そのほかを 1 とする。長音・促音・撥音（ー、ッ、ン）の挿入と削除は 0.5 とする。度合い = 1 − 距離 ÷ 長い方のモーラ数。
  - 0.6 以上のものを類似とし、度合いの高い順に上位 20 件を示す。文字が同一の商標は「同一」に分け、類似の一覧には入れない。
  - 区分の絞り込みは、`classes && $selected`（int 配列の重なり、GIN 索引）で DB の段階で行う。
- **Rationale**: 称呼キーを ASCII にすると、`pg_trgm` がデータベースのロケールに左右されない（C ロケールでは日本語の文字が trigram の対象外になる）。DB では粗く抽出し、日本語の音の近さはアプリで計算すると、テストしやすく（憲章 V）、閾値も調整しやすい。
- **検証**: 検証用データに、同一、称呼同一、1 音違い、濁音違い、長音の有無、無関係の組を入れ、SC-003（同一 100%）と SC-004（類似の 90% 以上が上位 20 件）を単体テストと結合テストで確かめる。
- **Alternatives considered**: `fuzzystrmatch` の `levenshtein` で全件を走査する案は、索引が使えず件数に比例して遅くなるため採らなかった。専用の検索エンジン（Elasticsearch など）は、メモリと運用の負荷が予算に合わない（憲章 VI）。

## R5. 非同期の実行と進捗（FR-019〜FR-021、SC-002）

- **Decision**:
  - 実行時に、候補ごとに pg-boss のジョブ（キュー `trademark-check`）を登録する。ジョブのデータは候補の ID だけとし、候補名を入れない（憲章 II）。
  - worker は候補を `running` にし、照合して結果を 1 トランザクションで書き、`done` にする。失敗したら 5 秒後に 1 回まで再試行する（1 回の試行は 30 秒で打ち切る）。再試行を使い切ったら `unknown` にして利用回数を戻す。
  - 候補ごとに期限（登録から 2 分）を持たせ、1 分ごとの定期ジョブ `expire-trademark-checks` が、期限を過ぎて終わっていない候補を `unknown` にして利用回数を戻す。worker は結果を書く前に候補の状態を確かめ、すでに `unknown` になったものは上書きしない（後から来た結果を捨てる）。
  - 画面は、実行中のあいだ 2 秒ごとに `router.refresh()` で読み直す（`docs/architecture.md` §2 の「画面が DB の結果を定期的に読み直す」）。
- **Rationale**: 画面を閉じても処理が続き（FR-020）、候補ごとに終わった順に見える（FR-019）。期限の判定を定期ジョブに分けると、worker が止まっていても 2 分で「不明」になる（FR-021）。
- **Alternatives considered**: Server-Sent Events は、接続を保つ負荷と実装の手間に比べ、2 秒の読み直しで NFR を満たせるため採らなかった。

## R6. 利用回数の上限と同時実行の制御（FR-025〜FR-029、FR-027a、SC-007）

- **Decision**:
  - 利用回数は、利用者と期間（`YYYY-MM`、日本時間）ごとの行（`usage_counters`）に、使った候補数を持つ。
  - 実行は 1 トランザクションで、`pg_advisory_xact_lock`（利用者の ID のハッシュ）で利用者ごとに直列にしてから、残りと実行中のチェック数を確かめ、チェック・候補・利用回数を書く。ジョブの登録はコミットの後に行う。登録に失敗した候補は `unknown` にして利用回数を戻す。
  - 利用回数を戻すときは、候補に記録した「数えた期間」の行から引く。候補の `charged` を false にしてから引くことで、二重に戻さない。
  - 上限値は `app_settings` の `usage.monthly_candidate_limit` に置き、ない場合は既定の 50 を使う（`005-operator-console` が変える）。
- **Rationale**: 同じ利用者の同時の実行でも合計が上限を超えない（SC-007）。期間の変わり目でも、受け付けた時点の期間で数えられる。
- **Alternatives considered**: 行ロック（`SELECT ... FOR UPDATE`）だけでは、行がまだない初回の同時実行を防げないため、アドバイザリロックを使う。

## R7. 比較表の列の拡張（FR-018）

- **Decision**: 比較表は「列の定義」の配列（`CheckColumn`: 見出し、候補ごとのセルの描画、完了の判定）で組み立てる。この機能では商標の列だけを登録する。`002`、`003` は、結果のテーブルと列の定義を足すだけで列を増やせる。
- **Rationale**: 後続の機能で比較表の画面を書き換えずに済む。

## R8. 公式の商標検索サービスへのリンク（FR-012）

- **Decision**: J-PlatPat の固定アドレスの形式（`https://www.j-platpat.inpit.go.jp/c1801/TR/JP-{出願番号}/40/ja`）で、出願番号からリンクを作る関数を 1 か所に置く。画面の取得はしない（FR-017）。
- **Rationale**: 詳細の取得を自動化せずに、利用者が公式の情報を確かめられる。形式は公開前に実際の番号で開けることを確かめる（quickstart §5）。

## R9. 機密性（FR-030〜FR-033）

- **Decision**:
  - チェックの読み出しは、すべて `user_id` を条件に含める関数（`findOwnedCheck`）を通す。本人のものでなければ 404 にする（存在を示さない）。
  - `checks.user_id` は `user.id` への外部キー（ON DELETE CASCADE）にし、候補と結果も連鎖して消す（`000-app-basic` data-model §10）。退会の後に worker が処理しようとした候補は見つからないので、何もせずに終わる。
  - ログには候補の ID と件数だけを出す。既存の伏せ字（`candidate`、`candidates` のキー）に、`inputText`、`normalizedText`、`reading`、`markText` を足す。
  - 商標の照合は自前の DB だけで行い、外部には何も送らない（FR-032 を満たす）。
- **Rationale**: 憲章 II（NON-NEGOTIABLE）。認可のテストで、他人のチェックの画面、やり直し、トップの一覧から見えないことを確かめる。
