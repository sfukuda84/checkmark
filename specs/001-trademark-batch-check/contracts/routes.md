# 契約: 画面とルート

**Feature**: `001-trademark-batch-check`

すべての画面は `requireUser()`（`000-app-basic`）を通す。未ログイン、未確認、未同意、停止の扱いは `000-app-basic` の contracts/routes.md に従う。

| パス | 種類 | 内容 | 要件 |
|---|---|---|---|
| `/` | Server Component | 新しいチェックへの導線、今月の残りの候補数と戻る日時、直近 5 件のチェック（実行日時、完了件数 / 全件数、確認中かどうか） | FR-022、FR-028 |
| `/checks/new` | Server Component ＋ フォーム | 候補の入力欄（1 行 1 件、`候補名 / ヨミ`）、区分の選択（説明つき、既定は全区分）、残りの候補数、実行ボタン。残りが 0 件なら実行できず、戻る日時を示す | FR-001〜FR-006、FR-028、US5 |
| `/checks/[id]` | Server Component ＋ 自動の読み直し | 比較表（候補を行、チェックの種類を列）。進み具合、選んだ区分、商標データの基準日と注意、簡易チェックの免責、該当商標の一覧と公式サービスへのリンク、「不明」の候補のやり直し | FR-007〜FR-024 |

## `/checks/[id]` の振る舞い

- 本人のチェックでなければ `notFound()`（404）。存在の有無を示さない（FR-030）。
- クエリ `merged=N`（N は 1 以上）があれば、「同じ候補を N 件まとめた」ことを上部に示す（FR-003）。
- 1 件でも `queued` か `running` の候補があれば、クライアントの部品が 2 秒ごとに `router.refresh()` を呼ぶ。すべて終わったら止める。
- 候補の行のセル（商標の列）:

| 候補の状態 | 表示 |
|---|---|
| `queued`、`running` | 「確認中」 |
| `done` かつ `identical` | 「同一の商標あり」と件数（100 件を超えたら「100 件以上」）。該当商標の一覧（番号、商標、称呼、権利者、区分、状態、リンク） |
| `done` かつ `similar` | 「類似の商標あり」と件数。似ている順の一覧（度合いを添える） |
| `done` かつ `none` | 「見つからなかった」。登録できるとは限らないことを添える |
| `unknown` | 「不明（確認できなかった）」とやり直しのボタン |

- 候補ごとに、照合に使った読みと、推定した読みかどうかを示す。推定した読みで結果が出た候補（または読みが得られなかった候補）には、「読みが違う場合は、読みを添えてもう一度チェックしてください」と `/checks/new?from=<id>` への導線を添える（入力欄に候補と読みを入れた状態で開く。FR-014a）。
- 全候補が「不明」で基準日が分からないときは、「商標データの基準日を確認できませんでした」と示す（照合が続いているように見せない）。
- 画面の上部に、簡易チェックの免責（FR-016）、基準日と調べた日時（FR-015）を示す。基準日が調べた日時より 30 日を超えて古ければ、注意を強調して示す（FR-015a）。
